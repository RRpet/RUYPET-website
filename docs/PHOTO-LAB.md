# PHOTO LAB V2 · 第一阶段

本功能位于现有 RUYPET DETAIL STUDIO 内，不是独立项目。顶部切换 PHOTO LAB / DETAIL BUILDER；两个工作区共用 `Project.assets`，修图记录为可选的 `Project.lab`。V1 项目文件可继续打开。无新增第三方依赖、无后台服务、不上传照片、不使用生成式 AI。

## 现有浏览器如何测试

云环境服务启动后，刷新原有浏览器页面即可加载最新前端（有未保存内容请先下载项目）；点击顶部 **PHOTO LAB · 批量修图**。本环境没有对外端口转发，不能把云机器的 localhost 当成你的 Mac 地址。Mac 仍按 README 双击 `启动.command`，使用同一个项目。

1. 输入拍摄批次名称，批量导入 JPG / PNG / WebP。原始文件字节以 data URL 保存，EXIF、ICC 保留在原片中；单张最大 80MB / 6500 万像素。CR3 不在此阶段支持范围内，先用佳能 DPP 导出带色彩配置的高质量 JPG。
2. 点击某张原片并选择预设，或“自动估计曝光 / 白平衡”。自动值只是建议；白平衡依赖亮部中性色假设，不能替代灰卡/色卡校准。
3. 微调曝光、亮度、色温、色调、高光、阴影、对比度、饱和度、背景均匀化和背景偏色校正。“保存当前参数为预设”可更新内置预设，或命名新预设。三个内置预设不是最终品牌色规范，也不是万能自动参数。
4. “应用到所选”或“应用到同拍摄批次”复制调整参数，不复制逐张主体保护画笔。切到单张后继续修改即构成单张覆盖。
5. 左右同时显示原图/优化图。切换到 100% 或 200% 检查真实像素，左右滚动同步。适应窗口预览最长边 1400px；100%/200% 加载完整原图，可能需要数秒。
6. 开启作用区域预览：橙色为背景候选、蓝色为手工保护。用保护主体/擦除保护画笔修正。画笔只阻止背景调整，不阻止全局色调处理。开启背景均匀化的照片必须逐张勾选已检查，才允许导出或加入商详；修改参数或批量应用会取消审核。
7. 上传官方透明 PNG 或自包含路径 SVG LOGO。位置、尺寸（相对图片宽）、边距（相对短边）、透明度及自定义坐标都可修改。LOGO 原始配置独立保存，不改写原始照片；SVG 为可靠的本机渲染栅格化成 PNG，不支持脚本、外部图片、字体/样式引用等。正式 LOGO 需用户自行提供。
8. 选择 JPG/PNG、原始分辨率或自定义宽度（等比例计算高度）。单张下载或所选批量 ZIP。ZIP 包含每张成品、处理参数与量测结果报告，单张失败会列入报告，不伪报全部成功。PNG 保留原透明通道，JPG 透明区域合成为白底。
9. “将所选优化图加入商详素材”生成新的 PNG 素材，原片保留，切换 DETAIL BUILDER 即可使用。调整以独立记录保留在 PHOTO LAB，导出图和商详素材是渲染后的成品。
10. **保存修图项目**下载 `.ruypet.json`，含原图、批次、逐张参数、保护笔迹、预设、LOGO 和原有商详。关闭浏览器后用“打开修图项目”恢复。没有自动浏览器缓存备份，必须确认下载成功。单张恢复原图参数不关闭独立 LOGO；如要完全无水印，选“不添加”。

## 模式 A 的真实处理流程

- EXIF 转正、解码 ICC 到 sRGB；在 sRGB canvas 中取像素。
- 全局曝光、白平衡增益在近似线性 RGB 中处理；高光/阴影按亮度权重处理；显示空间中做亮度、对比度和饱和度调整。没有几何变形、纹理生成、主体重绘或主动换色功能。主动白平衡/饱和度调整必然改变色值，应对照实物校准。
- 背景分析最长边 280px。从浅色、近中性的边界样本估计参考色，使用与边缘连通的保守候选区；避开亮度突变、较深阴影和彩色主体，对不确定边缘内缩、羽化。**这不是抠图蒙版，也不是语义分割。**
- 用背景样本拟合每通道二维二次低频亮度场（含 x/y/xy/x²/y²），向用户选择的参考亮度/中性方向做有限修正。每通道修正限幅 ±45/255，不把整幅画面提亮到纯白，也不填充生成背景。
- 在全分辨率上再次复核候选像素亮度与偏色，防止细线/暗色毛发落在缩小采样点之间。半透明输入 alpha 保留，不对其应用背景修正。
- 样本不足、边缘不可靠或中心几乎全部被判为背景时，降低背景强度并提示。可信度是启发式指标，不是分割模型概率。浅色狗、白色衣物或透纱仍可能和背景无法区分，必须保护画笔/降低强度/恢复原图。
- 暗部接触阴影尽量排除出作用区域，但不能承诺所有场景都正确。背景均匀度指标只衡量候选区域，主体变化指标也只基于候选区域的补集，不能作为商品真实性保证。

处理在 Web Worker 中逐张执行，预览任务被新参数取代时会取消；不会同时解码整批原尺寸图片。6500 万像素的上限仍需要充足内存，R7 原尺寸建议 Mac 至少 16GB，先保存项目再批量输出。ZIP 和项目文件会在内存中累积，大批次请拆分保存。无后端，因此无需 Python 服务或额外 Mac 安装步骤。

## 色彩与方向边界

`createImageBitmap(... imageOrientation: 'from-image', colorSpaceConversion: 'default')` 使用浏览器解码及色彩管理，sRGB canvas 进行处理。导出是新的 sRGB 栅格，不保留 Adobe RGB/P3 ICC 标签或 EXIF，方向已烘焙到像素，不再重复旋转。没有配置文件的图片按浏览器默认 sRGB 解释。不同显示器和浏览器仍可能有差异；不能保证 RAW、CMYK、HDR 或特殊 ICC 的专业印前保真。

测试包含一张带 Adobe RGB 兼容 ICC、EXIF orientation=6 的 JPEG；参考输出由 Pillow/LittleCMS 转为 sRGB 并转正，检查方向、尺寸和代表色块。该测试不能代替你实际 R7 文件的验证。生产前建议使用相同浏览器、经校准显示器和真实色卡。

## 模式 B：后续独立集成方案（未实现）

`src/photo-lab/segmentation.ts` 定义 `SubjectMattingProvider.segment`。输入真实图片、可选 trimap、取消信号；返回主体 alpha、独立接触阴影、不确定区域、模型与版本信息。当前 provider `available=false`，调用会明确报错，不会回退到模式 A 候选区。

可评估 ONNX Runtime Web + 经过许可证审查的主体分割模型生成初始 mask，再结合用户 trimap 和细节 matting 模型恢复毛发/透纱；不能把普通分割输出直接当作精细 alpha。也可为较大的 matting 模型增加仅监听 127.0.0.1 的 Python/PyTorch 本地服务（Apple Silicon 可评估 MPS），避免浏览器内存限制。第二阶段才增加依赖：固定模型版本、官方权重来源和 SHA-256、明确许可证、离线下载缓存路径，进行真实宠物照片基准测试。

候选模型必须评估非生成式 alpha matting（如 ViTMatte 类型）对宠物毛发、透明衣物、黑纱及 contact shadow 的实际能力；不得承诺普通人像模型适合宠物。需要人工 trimap、边缘修正和阴影层编辑；仅合成原始 RGB 与背景，不生成商品或动物像素。没有接入或下载未经验证的权重。

## 测试及证据

```sh
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e # 当前云机器
# Mac 开发测试使用：npx playwright install chromium，然后 npm run test:e2e
```

`tests/photo-lab.spec.ts` 验证实际像素处理、背景离散度、细线/色块/半透明纹理/阴影控制区、手工保护、批次和预设覆盖、LOGO、文件恢复、ZIP、商详素材复用、ICC/EXIF 和失败提示；`tests/editor.spec.ts` 回归原有编辑器。`tests/fixtures/generate.py` 仅为重建测试数据的开发脚本，使用 Pillow 与系统 ICC 测试配置；普通 Mac 用户不需要它。已提交的 fixtures 可直接运行浏览器测试，无需安装 Pillow。

证据文件位于 `docs/photo-lab-evidence/`：合成测试原图、优化图、参数和量测、批量 ZIP、可重新导入的演示项目、ICC/EXIF 量测及工作区截图。**这些是几何/材质合成控制图，不是用户狗狗照片，也不能证明真实毛发、纱料或产品色彩已通过验收。** 用户尚未提供实拍照片；收到样片后需对同一照片逐区比对，并人工确认商品与狗狗特征。
